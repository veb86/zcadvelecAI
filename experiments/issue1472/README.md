# HTTPServer: корректные CORS-заголовки (#1472)

## Причина и исправление

`TZCADHTTPServerManager.SetCORSHeaders` добавлял готовые строки `Name: Value`
в `AResponse.CustomHeaders`. Это `TStringList` с разделителем `=`.
В FPC 3.2.2 `TResponse.CollectHeaders` вызывает `GetNameValue`, получает пустое
имя и добавляет своё двоеточие. На проводе получается `: Name: Value`.

Теперь три заголовка задаются через `CustomHeaders.Values[Name] := Value`.
HTTP-сериализатор добавляет единственное двоеточие между именем и значением.

## Воспроизведение в ZCAD

1. Запустить `HTTPStart` (по умолчанию `127.0.0.1:5000`).
2. Выполнить `node -e "fetch('http://127.0.0.1:5000/ipc').then(r => r.json()).then(console.log)"`.
3. До исправления Node.js отклоняет ответ с некорректными заголовками.
   После исправления возвращается существующий JSON о доступности сервера.

## Автоматическая регрессия

Из корня репозитория, Node.js >= 18 и FPC с FCL-Web:

```sh
node experiments/issue1472/test_httpserver.mjs
```

Скрипт извлекает **текущие** `SetCORSHeaders` и `HandleRequest` из production-файла
в include-файлы временного каталога и компилирует маленький сервер FPC.
GUI, лог, исполнитель IPC, widgets и Grist заменены заглушками.
Используются настоящие `TFPHttpServer`, `TFPHTTPConnectionResponse` и сериализатор FPC.
Полная сборка ZCAD и Lazarus не требуются.

Для каждого из 11 случаев проверяются реальный HTTP/1.1-ответ через TCP и штатный
Node.js `fetch`: коды 200/204/400/404/405/500, допустимые имена заголовков,
ровно один экземпляр каждого CORS-заголовка с прежним значением, тело ответа
и JSON Content-Type для IPC. Проверены GET/POST `/ipc`, OPTIONS (также неизвестный
маршрут), пустое и пробельное тело, неверный метод, неизвестный маршрут, исключение
исполнителя, делегирование widgets и Grist. IPC-заглушка возвращает переданный JSON,
что проверяет неизменную передачу тела HTTP-обработчиком.

Сокеты и fetch ограничены 5 секундами; процесс сервера завершается и ожидается
в `finally`, временные файлы удаляются. В CI тест включён в `nodtests`, шаг ограничен
одной минутой.

Чувствительность к исходной ошибке (не меняя рабочее дерево):

```sh
git show cf9027df9:cad_source/zcad/velec/IPCserver/uzvhttpserver.pas > /tmp/httpserver-before.pas
node experiments/issue1472/test_httpserver.mjs /tmp/httpserver-before.pas
```

На исходнике до исправления первый GET `/ipc` завершается ошибкой `fetch failed`;
в диагностике видны три строки `: Access-Control-Allow-...`.
На исправленном исходнике проходят все 11 случаев (FPC 3.2.2, Node.js 26.13.0).

## Соответствие требованиям

| Требование issue | Реализация и проверка |
| --- | --- |
| Корректные HTTP/1.1-заголовки | `Values`; проверка сырых заголовков и Node.js fetch |
| Сохранить CORS | Прежние origin/methods/headers на всех проверенных маршрутах и ошибках |
| Сохранить `/ipc` и JSON | Изменён только `SetCORSHeaders`; проверены коды, тела, Content-Type |
| Сохранить очередь и выполнение в GUI-потоке | Код очереди и исполнителя не изменён |
| Не менять MCP-сервер | MCP-файлы не изменены |
| Не отключать проверку Node.js | Стандартный встроенный `fetch`, без специальных настроек парсера |

У issue нет обязательных подзадач; на момент реализации комментариев к issue и PR нет.
