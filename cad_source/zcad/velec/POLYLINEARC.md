## 1. Анализ содержимого файла `polylinearc.dxf`

Файл расположен в репозитории: `cad_source/test/polylinearc.dxf`.

### 1.1. Общие параметры

Раздел `HEADER` сообщает версию формата:

```
  9
$ACADVER
  1
AC1015
```

`AC1015` соответствует формату **AutoCAD 2000 (R15)**. Начиная с R14/2000, AutoCAD по умолчанию
сохраняет «лёгкие» полилинии как сущность **`LWPOLYLINE`** (оптимизированная 2D-полилиния), а не
как «тяжёлую» связку `POLYLINE`/`VERTEX`/`SEQEND`. Обе полилинии исследуемого файла записаны
именно как `LWPOLYLINE`.

Дополнительно из заголовка важны:

* `$FILLMODE = 1` — заливка широких сегментов включена;
* `$LTSCALE = 1.0` — глобальный масштаб типов линий;
* `$CELTSCALE = 1.0` — масштаб типа линии текущего объекта.

Вершины (X, Y):

| № | X | Y | Bulge (код 42) | Тип следующего сегмента |
|---|---|---|---|---|
| 1 | 564.4254694976425 | 233.6271617065995 | 0 | прямая (1→2) |
| 2 | 1157.534823092865 | 404.0614563048857 | **−0.6180044573622908** | **дуга (2→3)** |
| 3 | 1928.221817322253 | 375.6557378271355 | 0 | прямая (3→4) |
| 4 | 2457.403214522859 | 230.0764448633536 | — | (последняя вершина) |

**Ключевое наблюдение.** Код `42` появляется *после* координат вершины №2 и *до* координат
вершины №3. По правилам DXF Bulge относится к **сегменту, начинающемуся в той вершине, при которой
он указан**. Значит, дуговым является сегмент между вершинами 2 и 3. Значение отрицательное, то
есть дуга закручена по часовой стрелке (см. раздел 3). Полный численный разбор этого сегмента
приведён в разделе 3.4.

### 1.4. Выводы по разбору файла

* Обе полилинии хранятся как `LWPOLYLINE` (подкласс `AcDbPolyline`).
* Признак дугового сегмента — наличие группового кода `42` (Bulge) у соответствующей вершины.
* Если код `42` отсутствует или равен `0.0`, сегмент считается прямолинейным.
* В обоих объектах ширина нулевая (код 43 = 0), индивидуальные ширины (коды 40/41) не заданы.
  Это означает, что вопрос «дуга + ширина» в самом файле не иллюстрируется напрямую и должен
  исследоваться отдельно (разделы 4 и 6).

## 2. Способы хранения дуговых сегментов в DXF

### 2.1. Сущность `LWPOLYLINE` (современный способ)

`LWPOLYLINE` — оптимизированная 2D-полилиния (введена в R14/AutoCAD 2000). Все вершины лежат в
одной плоскости (общая высота `elevation`, код 38), а ориентация плоскости задаётся вектором
выдавливания (extrusion, коды 210/220/230). Структура одного объекта:

| Групповой код | Назначение | Кратность |
|---|---|---|
| `100` = `AcDbPolyline` | маркер подкласса | 1 |
| `90` | число вершин | 1 |
| `70` | флаги полилинии (бит 0 — замкнутость, бит 128 — plinegen) | 1 |
| `43` | постоянная ширина (если задана, отменяет 40/41) | 0..1 |
| `38` | высота плоскости (elevation) | 0..1 |
| `39` | толщина (thickness, «выдавливание» в 3D) | 0..1 |
| `10`/`20` | X/Y координаты вершины | по числу вершин |
| `40` | начальная ширина сегмента (startwidth) | 0..1 на вершину |
| `41` | конечная ширина сегмента (endwidth) | 0..1 на вершину |
| **`42`** | **Bulge (выпуклость) сегмента** | **0..1 на вершину** |
| `91` | идентификатор вершины (vertex identifier) | 0..1 на вершину |
| `210`/`220`/`230` | вектор выдавливания | 0..1 |

Группы вершины (`10/20`, при необходимости `40/41/42/91`) повторяются `90` раз. **Bulge (42)
является необязательным для каждой вершины:** он записывается только тогда, когда сегмент,
начинающийся в этой вершине, — дуга. Отсутствие кода 42 эквивалентно `bulge = 0` (прямая).

### 2.2. Сущность `POLYLINE` / `VERTEX` / `SEQEND` (классический способ)

«Тяжёлая» полилиния состоит из заголовочной сущности `POLYLINE` и последовательности отдельных
сущностей `VERTEX`, завершаемой `SEQEND`. Этот способ используется для 3D-полилиний, полигональных
сетей, а также читается из старых файлов.

* `POLYLINE`:
  * `70` — флаги (бит 0 — замкнутость, биты для 3D-полилинии/сети и т. п.);
  * `40`/`41` — ширина по умолчанию (start/end) для всех вершин;
  * `66` — «vertices follow» (устаревший признак).
* `VERTEX` (для каждой вершины):
  * `10`/`20`/`30` — координаты X/Y/Z вершины;
  * `40`/`41` — начальная/конечная ширина данного сегмента;
  * **`42`** — **Bulge данного сегмента** (тот же смысл, что и в `LWPOLYLINE`);
  * `70` — флаги вершины;
  * `50` — направление касательной (tangent), если задано.
* `SEQEND` — конец списка вершин.

Принцип хранения дуги **одинаков** в обоих представлениях: код `42` (Bulge) у вершины, с которой
начинается дуговой сегмент. Различается только «обёртка» (единая сущность против связки сущностей).

### 2.3. Особенности замкнутых полилиний

* Замкнутость задаётся **битом 0 кода 70** (`70 = 1` — замкнута).
* У замкнутой полилинии существует дополнительный (замыкающий) сегмент от последней вершины к
  первой. Bulge этого замыкающего сегмента хранится в коде `42` **последней** вершины.
* При нулевой замкнутости (`70 = 0`, как в обоих объектах файла) замыкающего сегмента нет, и код
  42 последней вершины не имеет геометрического смысла (сегмента после неё не существует).

### 2.4. Различия между версиями DXF

* **До R14:** только `POLYLINE`/`VERTEX`. Bulge уже поддерживался (код 42 у `VERTEX`).
* **R14 / AutoCAD 2000 (AC1014/AC1015):** введён `LWPOLYLINE`; стал форматом по умолчанию для
  плоских 2D-полилиний. Именно эту версию (`AC1015`) имеет исследуемый файл.
* **Современные версии (AC1018+ / 2004 и новее):** структура `LWPOLYLINE` не изменилась; добавлены
  лишь сопутствующие возможности (идентификаторы вершин `91`, расширенные данные). Способ хранения
  дуги через Bulge остаётся стабильным во всех версиях DXF.

Таким образом, для целей ZCAD достаточно поддержать **код 42** в обоих представлениях — этого
хватит для чтения дуговых сегментов из файлов любых версий.

## 3. Механизм Bulge

### 3.1. Назначение

**Bulge (выпуклость)** — это компактный числовой параметр, который превращает прямолинейный
сегмент полилинии между двумя соседними вершинами в дугу окружности. Он хранится одним
вещественным числом (код 42) и позволяет не хранить ни центр, ни радиус, ни углы дуги — всё это
вычисляется из пары вершин и значения Bulge.

### 3.2. Математический смысл

Bulge определяется как тангенс четверти центрального угла дуги:

```
bulge = tan(θ / 4)
```

где `θ` — центральный (включённый) угол дуги, опирающейся на хорду между двумя вершинами.

Геометрически Bulge равен отношению **высоты сегмента дуги (сагитты `s`)** к **половине длины
хорды**:

```
bulge = s / (L/2) = 2s / L
```

где `L` — длина хорды, `s` — расстояние от середины хорды до самой дальней точки дуги (стрела
прогиба). Отсюда:

* `bulge = 0` → дуга вырождается в прямую (`θ = 0`);
* `bulge = 1` → `θ = 180°` (полуокружность, дуга «приподнята» ровно на половину хорды);
* `|bulge| < 1` → дуга меньше полуокружности (малая дуга);
* `|bulge| > 1` → дуга больше полуокружности (большая дуга).

### 3.3. Связь с радиусом, центром и углами

Пусть вершины сегмента — `P1 = (x1, y1)` и `P2 = (x2, y2)`, длина хорды `L = |P2 − P1|`.

**Центральный угол:**

```
θ = 4 · arctan(|bulge|)
```

**Радиус:**

```
R = L / (2 · sin(θ/2))
```

Эквивалентная формула без явного вычисления θ (удобна численно):

```
R = L · (1 + bulge²) / (4 · |bulge|)
```

**Сагитта (стрела прогиба):**

```
s = |bulge| · L / 2
```

**Центр дуги.** Середина хорды `M = (P1 + P2)/2`. Единичный вектор вдоль хорды
`u = (P2 − P1)/L`. Единичная нормаль к хорде `n = (−u_y, u_x)` (поворот на +90°). Апофема (расстояние
от середины хорды до центра):

```
d = R · cos(θ/2) = R − s   (по модулю; знак учитывает направление)
```

Центр:

```
C = M + sign(bulge) · (−n) · d        (направление нормали выбирается по знаку Bulge)
```

На практике центр удобнее вычислять напрямую через перпендикуляр к хорде, сдвинутый на `d` в
сторону, противоположную выпуклости. Точная сторона зависит от знака Bulge.

**Углы:**

```
startAngle = atan2(y1 − Cy, x1 − Cx)
endAngle   = atan2(y2 − Cy, x2 − Cx)
```

### 3.4. Направление дуги и знак Bulge

* **Bulge > 0** — дуга строится **против часовой стрелки (CCW)** от `P1` к `P2`; выпуклость
  направлена влево от направления хорды `P1→P2`.
* **Bulge < 0** — дуга строится **по часовой стрелке (CW)**; выпуклость направлена вправо.
* **Bulge = 0** — прямой сегмент.

Знак влияет на то, по какую сторону от хорды лежит дуга и в каком направлении она обходится. Это
критично для корректного построения смещённых границ при ненулевой ширине (раздел 4) и для
распределения штрихов типа линии (раздел 5).

### 3.5. Числовой пример (дуговой сегмент полилинии №2)

Возьмём реальный сегмент из файла: вершина 2 `P1 = (1157.534823092865, 404.0614563048857)`,
вершина 3 `P2 = (1928.221817322253, 375.6557378271355)`, `bulge = −0.6180044573622908`.

Расчёт (проверено численно):

| Величина | Формула | Значение |
|---|---|---|
| Длина хорды `L` | `|P2 − P1|` | **771.2103** |
| Центральный угол `θ` | `4·arctan(|bulge|)` | **2.21421 рад = 126.8650°** |
| Радиус `R` | `L/(2·sin(θ/2))` | **431.1289** |
| Длина дуги `Larc` | `R·θ` | **954.6107** |
| Сагитта `s` | `|bulge|·L/2` | **238.3057** |
| Центр `C` | см. 3.3 | **(1535.7761, 197.1663)** |
| Начальный угол | `atan2(y1−Cy, x1−Cx)` | **151.3217°** |
| Конечный угол | `atan2(y2−Cy, x2−Cx)` | **24.4567°** |
| Направление | знак Bulge | **по часовой стрелке (CW)** |

Проверка: `tan(θ/4) = tan(126.8650°/4) = tan(31.7162°) = 0.6180044…` — совпадает с `|bulge|`,
что подтверждает корректность формулы `bulge = tan(θ/4)`.

Обратите внимание: **длина дуги (954.61) почти на четверть больше длины хорды (771.21)**. Этот факт
напрямую влияет на распределение типа линии (раздел 5): штрихи должны раскладываться по дуге, а не
по хорде.

### 3.6. Схема

```
                    .  -  -  .                       <- дуга (R = 431.13)
                .                 .
            .         сагитта s        .
          P1 - - - - - -|- - - - - - - P2            <- хорда (L = 771.21)
            \           |             /
              \         | d           /
                \       |           /
                  \     |         /                   θ = 126.865° (центральный угол)
                    \   |       /
                      \ |     /
                        C  (центр дуги)
```

Для приведённого примера Bulge отрицательный, поэтому фактическая дуга выпукла «вниз» (по часовой
стрелке от `P1` к `P2`); схема выше показана условно «вверх» для наглядности обозначений.

## 4. Отображение дуговых сегментов с учётом Width

Этот раздел — один из основных. Он посвящён тому, как корректно нарисовать **утолщённый дуговой
сегмент** и как состыковать его с соседями.

### 4.1. Модель ширины полилинии

* **Постоянная ширина (код 43).** Применяется ко всем сегментам, если задана. В исследуемом файле
  она равна 0.
* **Переменная ширина (коды 40/41).** Для каждого сегмента задаётся начальная (`startwidth`) и
  конечная (`endwidth`) ширина. Ширина может линейно меняться вдоль сегмента (получается
  «трапеция» у прямой и «клин/кольцевой сектор переменной толщины» у дуги).
* Если для сегмента заданы и 43, и 40/41, приоритет имеет постоянная ширина 43 (поведение AutoCAD).

Геометрически утолщённый сегмент — это **полоса**, ограниченная двумя кривыми (внешней и
внутренней границей) и двумя торцами. Заливка этой полосы управляется `$FILLMODE`.

### 4.2. Утолщённая прямая (опорный случай)

Для прямого сегмента с началом `P1` (ширина `w1`) и концом `P2` (ширина `w2`):

* Нормаль к сегменту `n = (−u_y, u_x)`, где `u` — единичный вектор `P1→P2`.
* Четыре угла полосы (квадрат/трапеция):
  ```
  P1 + n·(w1/2),  P2 + n·(w2/2),  P2 − n·(w2/2),  P1 − n·(w1/2)
  ```

Именно так ZCAD уже строит ширину прямых сегментов: метод `CalcWidthSegment()` формирует
четырёхугольник `quad[0..3]` в записи `GLLWWidth.quad`
(`cad_source/zengine/core/entities/uzeentlwpolyline.pas`). Это удобная опорная точка для
обобщения на дуги.

### 4.3. Утолщённая дуга

Утолщённая дуга — это **кольцевой сектор**. Для дуги с центром `C`, радиусом `R` (по осевой линии)
и постоянной полушириной `h = w/2`:

* **Внешняя граница** — концентрическая дуга радиуса `R + h` (тот же центр `C`, те же углы).
* **Внутренняя граница** — концентрическая дуга радиуса `R − h` (тот же центр, те же углы).
* **Торцы** — отрезки вдоль радиусов в начальной и конечной точках.

Это фундаментальное упрощение: **смещение дуги на постоянную величину — это снова дуга** (в
отличие от смещения, например, сплайна). Поэтому утолщённую дугу постоянной ширины можно построить
точно, без тесселяции, тремя дугами/отрезками.

**Опасный случай:** если `R − h ≤ 0` (полуширина больше радиуса осевой линии), внутренняя граница
«выворачивается» через центр. Такие конфигурации (малый радиус + большая ширина) требуют особой
обработки: либо ограничение внутренней границы центром, либо построение самопересекающейся
заливки. AutoCAD при заливке таких сегментов даёт характерные «зонтичные» артефакты; реализация
должна это предусматривать (см. 4.6).

### 4.4. Переменная ширина на дуге

Если `w1 ≠ w2`, смещение уже **не концентрическая дуга** — внешняя и внутренняя границы становятся
кривыми переменного радиального смещения (близки к спиралям Архимеда в полярных координатах
относительно `C`). Точного представления простой дугой нет. Практический подход всех CAD —
**тесселяция**: дуга разбивается на `N` коротких хорд, на каждой строится трапеция (как в 4.2) с
интерполированной шириной. Чем больше `N`, тем плавнее граница.

Рекомендуемое правило выбора числа сегментов тесселяции — по допуску на хорду (максимальное
отклонение хорды от дуги):

```
N = ceil( θ / (2 · arccos(1 − tol/R)) )
```

где `tol` — допустимое отклонение в единицах чертежа (например, доля пикселя в текущем масштабе
экрана). Это связывает детализацию с текущим зумом (LOD), что согласуется с уже имеющейся в ZCAD
логикой уровней детализации в `DrawGeometry()`.

### 4.5. Сопряжение соседних сегментов (стыки)

В местах соединения двух сегментов (прямая–дуга, дуга–прямая, дуга–дуга) внешние и внутренние
границы соседей нужно **состыковать**, иначе появятся разрывы или наложения. Основные подходы:

* **Miter (ус).** Границы продлеваются до пересечения. ZCAD уже выполняет miter-стыковку для
  прямых сегментов в `CalcWidthSegment()`. Для дуг точка пересечения ищется между прямой/дугой
  или дугой/дугой (квадратные уравнения), что усложняет код.
* **Bevel (срез).** Внешние концы просто соединяются отрезком — проще и устойчивее при больших
  углах, где miter «убегает» в бесконечность.
* **Round (скругление).** Между концами вставляется дополнительная дуга по внешнему углу.

Ключевая тонкость: **касательная дуги в точке стыка** направлена не вдоль хорды, а перпендикулярно
радиусу. Поэтому нормаль для смещения границы на конце дугового сегмента нужно брать из
**касательной к дуге**, а не из направления хорды. Несоблюдение этого — частый источник «заломов» в
стыках дуга↔прямая.

### 4.6. Замкнутые полилинии и особые правила

* В замкнутой полилинии стыкуется и последний сегмент с первым — нужно замкнуть miter-цепочку по
  кругу.
* Для малых радиусов и больших ширин (`R − h ≤ 0`, см. 4.3) необходима защита от вырождения
  внутренней границы.
* При `$FILLMODE = 0` полилиния рисуется только осевой линией (контуры ширины не заливаются) —
  быстрый путь отрисовки, полезный как fallback на низком LOD.

### 4.7. Резюме сложностей по Width

| Случай | Сложность | Подход |
|---|---|---|
| Дуга, постоянная ширина | низкая | три концентрические дуги/торцы (точно) |
| Дуга, переменная ширина | средняя | тесселяция в трапеции |
| Стык прямая↔дуга | средняя | miter по касательной к дуге |
| Стык дуга↔дуга | высокая | пересечение двух смещённых дуг |
| Малый радиус + большая ширина | высокая | защита от выворота внутренней границы |
| Замкнутая полилиния | средняя | круговая miter-цепочка |

## 5. Отображение дуговых сегментов с учётом Linetype

Второй основной раздел. Тип линии (DASHED, HIDDEN, CENTER и др.) — это периодический шаблон из
штрихов и пробелов, который нужно «уложить» вдоль геометрии сегмента.

### 5.1. Длина дуги, а не хорды

Главный принцип: шаблон типа линии распределяется по **фактической длине дуги** (`Larc = R·θ`), а
не по длине хорды. Использование хорды дало бы заметную ошибку — в нашем примере хорда 771.21 при
длине дуги 954.61 (разница ~24%), и штрихи «съезжали» бы. Поэтому позиция каждого штриха
параметризуется длиной дуги от её начала:

```
arcParam(t) = R · (currentAngle(t) − startAngle)
```

Каждой границе штриха/пробела соответствует длина `ℓ`, по которой вычисляется угол
`α = startAngle ± ℓ/R`, а затем точка на дуге `C + R·(cos α, sin α)`. Так штрихи получаются
геометрически правильными дугами/точками, расположенными по дуге.

### 5.2. Непрерывность шаблона между сегментами

AutoCAD поддерживает **накопленную фазу** (offset) шаблона вдоль всей полилинии: тип линии «течёт»
непрерывно от сегмента к сегменту, не сбрасываясь на каждой вершине. Реализация хранит «остаток»
шаблона (сколько штриха/пробела ещё не выложено) и передаёт его в следующий сегмент. Это даёт
ровный рисунок на переходах:

* **линия → дуга:** остаток фазы с прямого сегмента продолжается по дуге;
* **дуга → линия:** остаток фазы с дуги продолжается по прямой;
* **дуга → дуга:** фаза переходит между дугами разного радиуса без разрыва.

Важно: длина для накопления фазы на дуге берётся как длина дуги (5.1).

### 5.3. Режим генерации шаблона: PLINEGEN (бит 128 кода 70)

У полилинии есть флаг **`70` бит 128** (`PLINEGEN`/`$PLINEGEN`):

* **Сброшен (по умолчанию):** шаблон типа линии генерируется **отдельно для каждого сегмента**,
  начинаясь и заканчиваясь штрихом в каждой вершине. На дугах это означает локальный пересчёт по
  длине дуги в пределах сегмента.
* **Установлен (PLINEGEN = 1):** шаблон генерируется **непрерывно по всей полилинии** (как в 5.2),
  игнорируя вершины. Тогда нужна сквозная параметризация по сумме длин (прямых — по длине,
  дуг — по длине дуги).

Поддержка обоих режимов важна для визуального соответствия AutoCAD.

### 5.4. Поведение конкретных типов линий

* **DASHED** — равномерные штрихи и пробелы; на дуге штрихи становятся короткими дугами.
* **HIDDEN** — короткие штрихи; чувствителен к точности длины дуги (мелкий шаг, ошибки заметнее).
* **CENTER** — чередование длинного штриха и точки/короткого штриха; для симметрии относительно
  центров важна корректная фаза на стыках.
* **Пользовательские типы (.lin)** — могут содержать текст и формы (shapes) в штрихах. На дуге
  встроенный текст обычно **не вращается по касательной** в простом приближении, но AutoCAD
  ориентирует элементы вдоль направления линии — это дополнительный (необязательный на первом
  этапе) уровень сложности.

### 5.5. Масштаб типа линии

На итоговую длину штрихов влияют `$LTSCALE` (глобальный), `$CELTSCALE` (масштаб объекта) и масштаб
аннотаций. Длины шаблона из `.lin`-файла умножаются на эти коэффициенты до раскладки по дуге. В
исследуемом файле оба масштаба равны 1.0.

### 5.6. Резюме сложностей по Linetype

| Аспект | Сложность | Замечание |
|---|---|---|
| Раскладка штрихов по длине дуги | средняя | параметризация углом `ℓ/R` |
| Непрерывность фазы между сегментами | средняя | хранить остаток шаблона |
| Режим PLINEGEN (посегментно/сквозь) | средняя | два режима по биту 128 |
| Штрихи как дуги (а не хорды) | средняя | геометрически правильно |
| Текст/формы в пользовательских типах | высокая | можно отложить |

## 6. Поведение AutoCAD при работе с дуговыми сегментами

Сводка наблюдаемого поведения AutoCAD (и совместимых систем — BricsCAD, GstarCAD), важного для
сопоставимой реализации в ZCAD.

### 6.1. Создание и редактирование

* Команда `PLINE` имеет опцию **Arc**, переключающую ввод в режим дуговых сегментов; внутренне это
  записывается как Bulge у вершины.
* Команда `PEDIT` позволяет: преобразовать сегмент **Line ↔ Arc**, изменить ширину (`Width`),
  редактировать отдельные вершины (`Edit vertex`), задать замкнутость (`Close`/`Open`), включить
  `Ltype gen` (PLINEGEN).
* Ручки (grips) на дуговом сегменте позволяют тянуть среднюю точку дуги — это меняет Bulge,
  сохраняя концевые вершины.

### 6.2. Преобразования Line ↔ Arc и изменение Bulge

* **Line → Arc:** AutoCAD задаёт сегменту ненулевой Bulge (по умолчанию строит дугу через заданную
  точку или по касательной к соседнему сегменту).
* **Arc → Line:** Bulge сбрасывается в 0.
* **Изменение Bulge:** концевые вершины неподвижны, меняется только кривизна (радиус, центр, углы
  пересчитываются по формулам раздела 3).

### 6.3. Width на дугах

* Постоянная ширина рисуется как кольцевой сектор (раздел 4.3).
* Переменная ширина — плавный переход (внутренне тесселируется при отрисовке/печати).
* При `FILL on` сектор заливается; при `FILL off` рисуется только контур осевой линии.
* `EXPLODE` разбивает полилинию на отдельные сущности: **дуговые сегменты становятся `ARC`**,
  прямые — `LINE`. При этом ширина теряется (стандартные `ARC`/`LINE` её не имеют). Это
  подтверждает, что Bulge — лишь способ хранения дуги внутри полилинии.

### 6.4. Linetype и регенерация

* По умолчанию шаблон типа линии перезапускается в каждой вершине; при `Ltype gen = ON` (PLINEGEN)
  — течёт по всей длине, включая дуги (раздел 5.3).
* Длина для раскладки шаблона на дуге — фактическая длина дуги.
* `REGEN` пересчитывает тесселяцию дуг под текущий зум; на больших зумах дуга всегда выглядит
  гладкой, что говорит об адаптивной тесселяции по экранному допуску.

### 6.5. Практические следствия для ZCAD

ZCAD стремится к совместимости с AutoCAD-файлами, поэтому при реализации важно повторить:
непрерывность фазы Linetype (PLINEGEN), кольцевой сектор для ширины, поведение `EXPLODE`
(дуга → `GDBObjArc`), приоритет постоянной ширины над переменной.

## 7. Реализация дуговых сегментов в библиотеке ezdxf

[ezdxf](https://github.com/mozman/ezdxf) (автор Manfred Moitzi) — зрелая Python-библиотека
чтения/записи DXF. Её решения — хороший эталон. Ниже — ключевые модули и идеи (ссылки на пути в
репозитории ezdxf).

### 7.1. Представление LWPOLYLINE

* `src/ezdxf/entities/lwpolyline.py` — класс `LWPolyline`. Вершина представлена кортежем
  **`(x, y, start_width, end_width, bulge)`** — Bulge является штатным, равноправным полем вершины.
* Формат точек настраивается атрибутом `format` (например, `'xyb'` — координаты + bulge), что
  отражает: bulge — неотъемлемая часть вершины, а не отдельная сущность.
* `src/ezdxf/entities/polyline.py` — «тяжёлые» `Polyline`/`DXFVertex`; bulge хранится в атрибуте
  вершины `dxf.bulge`.

### 7.2. Преобразование Bulge → геометрия

Центральный модуль — **`src/ezdxf/math/_bulge.py`** (реэкспортируется из `ezdxf.math`). Ключевые
функции:

* `bulge_to_arc(start_point, end_point, bulge)` → `(center, start_angle, end_angle, radius)` —
  ровно то преобразование, что описано в разделе 3.3.
* `bulge_center(start_point, end_point, bulge)` → центр дуги.
* `bulge_radius(start_point, end_point, bulge)` → радиус.
* `arc_to_bulge(center, start_angle, end_angle, radius)` → обратное преобразование (геометрия →
  bulge), нужное при записи.

Эти функции инкапсулируют ровно ту математику, которую предстоит перенести в ZCAD (на Pascal).

### 7.3. Тесселяция и обход вершин

* Метод `LWPolyline.virtual_entities()` / `Polyline.virtual_entities()` «разворачивает» полилинию в
  набор примитивов `Line` и `Arc` — прямой аналог `EXPLODE` в AutoCAD (раздел 6.3).
* `src/ezdxf/path/` (модуль `Path`) умеет аппроксимировать любую геометрию, включая дуги из bulge,
  набором отрезков с заданным допуском — образец адаптивной тесселяции (раздел 4.4).
* Конструкция дуги: `src/ezdxf/math/_construct.py`, классы дуг в `src/ezdxf/math/arc.py`
  (`ConstructionArc`) — методы вычисления точек, углов, ограничивающего прямоугольника.

### 7.4. Обработка Width и Linetype

* **Width:** ezdxf хранит `start_width`/`end_width` на вершину и `const_width`, но как библиотека
  обмена данными **не выполняет растровую отрисовку утолщённых дуг сама** — это делает рендер-слой
  (`ezdxf.addons.drawing`), который тесселирует и строит контуры. То есть «толстую дугу» рисует не
  ядро, а слой визуализации — полезное архитектурное разделение для ZCAD.
* **Linetype:** ezdxf хранит определения типов линий (`src/ezdxf/entities/ltype.py`,
  `tools/standards`), но раскладку штрихов вдоль геометрии выполняет рендер-аддон
  (`ezdxf.addons.drawing.line_renderer`), а не ядро. Это подтверждает: распределение Linetype —
  задача отрисовки, а не хранения.

### 7.5. Выводы по ezdxf

* Bulge в ezdxf — **штатное поле вершины**, а не отдельная сущность. ZCAD стоит хранить bulge так же
  — параллельным массивом к уже существующему массиву ширин.
* Готовый, проверенный набор формул `bulge_to_arc` / `bulge_radius` / `bulge_center` можно прямо
  использовать как спецификацию для Pascal-реализации.
* Архитектурно ezdxf разделяет **хранение** (ядро) и **отрисовку толщины/типа линии** (рендер-слой).
  Это совпадает с устройством ZCAD (ядро сущностей + абстрактный drawer) и подсказывает, где
  размещать новую логику.

## 8. Геометрические алгоритмы для работы с дуговыми сегментами

Сводка вычислений, которые потребуются при реализации. Обозначения: `P1, P2` — вершины сегмента,
`b` — bulge, `C` — центр, `R` — радиус, `θ` — центральный угол, `α0/α1` — начальный/конечный угол.

### 8.1. Базовые величины из Bulge

```
L   = |P2 − P1|                       (длина хорды)
θ   = 4·arctan(|b|)                    (центральный угол)
R   = L·(1 + b²) / (4·|b|)             (радиус)
s   = |b|·L / 2                        (сагитта)
C   = bulge_center(P1, P2, b)          (центр, см. 3.3)
α0  = atan2(P1.y − C.y, P1.x − C.x)
α1  = atan2(P2.y − C.y, P2.x − C.x)
dir = sign(b)                          (>0: CCW, <0: CW)
```

### 8.2. Длина дуги и длина полилинии со смешанными сегментами

```
ДлинаДуги(сегмент)   = R · θ
ДлинаПрямой(сегмент) = |P2 − P1|
ДлинаПолилинии       = Σ по сегментам (дуга → R·θ, прямая → |P2−P1|)
```

Полная длина нужна для Linetype (раздел 5), измерений, площади и команд редактирования.

### 8.3. Точка на дуге по параметру

```
α(t) = α0 + dir · t · θ,   t ∈ [0, 1]
Point(t) = C + R · (cos α(t), sin α(t))
```

### 8.4. Касательная к дуге

```
Tangent(t) = dir · (−sin α(t), cos α(t))      (единичный вектор направления движения)
```

Касательная нужна для построения нормалей смещения ширины (раздел 4.5) и ориентации элементов
Linetype.

### 8.5. Центр, радиус — см. 8.1. Площадь сектора (вклад дуги в площадь полилинии)

Площадь замкнутой полилинии с дугами = площадь многоугольника по вершинам (формула шнурков) ±
площади круговых сегментов (по знаку Bulge):

```
S_сегмента_дуги = (R²/2)·(θ − sin θ)        (площадь кругового сегмента)
```

ZCAD уже вычисляет поле `Square` для полилинии (`uzeentlwpolyline.pas`); при добавлении дуг эту
формулу нужно расширить вкладом сегментов.

### 8.6. Ограничивающий прямоугольник (Bounding Box) дуги

BBox дуги — это не BBox её концов: дуга может выходить за пределы хорды на сагитту, а также
«цеплять» крайние точки по осям (углы 0°, 90°, 180°, 270°). Алгоритм:

1. Включить `P1` и `P2`.
2. Для каждого из углов `k·90°` (k = 0..3): если этот угол попадает в дуговой интервал `[α0, α1]`
   (с учётом направления `dir`), добавить точку `C + R·(cos, sin)` соответствующей оси.

Без шага 2 BBox дуг будет занижен — частая ошибка.

### 8.7. Принадлежность точки дуге (hit-test)

```
1. d = |Q − C|;  если |d − R| > tol → точка не на окружности.
2. β = atan2(Q.y − C.y, Q.x − C.x);  проверить, лежит ли β в дуговом интервале
   [α0, α1] с учётом направления dir.
```

Нужно для выбора объекта курсором, привязок (osnap: ближайшая точка, середина дуги, центр,
квадранты).

### 8.8. Смещённые (offset) дуги для отображения ширины

```
Внешняя дуга:  тот же C, радиус R + w/2,  те же α0/α1
Внутренняя:    тот же C, радиус R − w/2,  те же α0/α1   (контроль R − w/2 > 0)
```

Точно для постоянной ширины (раздел 4.3); для переменной — тесселяция (4.4).

### 8.9. Адаптивная тесселяция дуги в полилинию точек

```
N = max(2, ceil( θ / (2·arccos(1 − tol/R)) ))
точки: Point(i/N), i = 0..N
```

`tol` берётся из текущего экранного масштаба (LOD) — согласуется с механизмом детализации ZCAD.

## 9. Текущее состояние ZCAD и выявленные сложности реализации

Раздел опирается на исследование исходного кода ZCAD (пути и строки приведены для ориентира).

### 9.1. Что уже есть

| Компонент | Файл | Состояние |
|---|---|---|
| Класс полилинии `GDBObjLWPolyline` | `cad_source/zengine/core/entities/uzeentlwpolyline.pas` | хранит вершины и ширину, **без bulge** |
| Запись ширины сегмента `GLLWWidth` (`startw/endw/quad`) | там же | есть, рассчитывает quad для **прямых** |
| Отрисовка `DrawGeometry()` / `CalcWidthSegment()` | там же | quad-заливка, miter — **только прямые** |
| Класс дуги `GDBObjArc` (R, StartAngle, EndAngle, тесселяция) | `cad_source/zengine/core/entities/uzeentarc.pas` | полноценная сущность дуги |
| Поле bulge в низкоуровневом DWG | `cad_source/components/fpdwg/dwgproc.pp` (`TDWGLWPolylineVertex.Bulge`) | **читается**, но не пробрасывается выше |
| Парсер proxy-LWPOLYLINE | `cad_source/zengine/core/entities/uzeentproxy/uzeentproxyparserlwpolyline.pas` | bulge **читается и игнорируется** (прямой комментарий в коде) |
| Идентификаторы типов | `cad_source/zengine/core/uzeconsts.pas` (`GDBLWPolylineID`, `GDBarcID`) | есть |

Показательно: на уровне DWG bulge уже доходит до структуры `TDWGLWPolylineVertex.Bulge`, но при
конвертации в `GDBObjLWPolyline` (`cad_source/zengine/fileformats/dwg/entities/uzedwgentlwpolyline.pas`)
**не копируется**. В proxy-парсере есть прямой комментарий: «Выпуклость (Bulge) не тесселируется —
сегменты рисуются прямыми».

### 9.2. Чего не хватает

1. **Хранилище bulge** в `GDBObjLWPolyline` (массив параллельно ширинам).
2. **Чтение DXF:** в `LoadFromDXF()` нет ветки для кода `42`.
3. **Запись DXF:** в `SaveToDXF()` код `42` не выводится.
4. **DWG-импорт:** `Bulge` не переносится из `Props.Vertices[i].Bulge`.
5. **Proxy-парсер:** bulge читается, но отбрасывается.
6. **Тесселяция/геометрия:** `CalcWidthSegment()` исходит из прямых сегментов.
7. **Отрисовка ширины** на дуге (кольцевой сектор / тесселяция).
8. **Отрисовка Linetype** вдоль дуги (раскладка по длине дуги, фаза, PLINEGEN).

### 9.3. Сложности, ранжированные по риску

* **Высокий риск:**
  * стык дуга↔дуга и дуга↔прямая при ненулевой ширине (miter по касательной, пересечение
    смещённых дуг);
  * малый радиус + большая ширина (выворот внутренней границы, раздел 4.3);
  * непрерывность Linetype через дуги с учётом PLINEGEN и накопленной фазы.
* **Средний риск:**
  * переменная ширина на дуге (тесселяция, выбор `N`);
  * корректный BBox дуги (раздел 8.6), площадь с дугами (8.5);
  * привязки/hit-test к дуговым сегментам (8.7).
* **Низкий риск:**
  * добавление поля bulge и чтение/запись кода 42 (механическая часть);
  * постоянная ширина на дуге (три концентрические дуги, точно).

### 9.4. Точки интеграции (для будущего этапа, без реализации сейчас)

| Действие | Где | Примечание |
|---|---|---|
| Добавить массив bulge | `uzeentlwpolyline.pas` (рядом с `Width2D_in_OCS_Array`) | параллельно ширинам |
| Чтение кода 42 | `LoadFromDXF()` | ветка `42:` |
| Запись кода 42 | `SaveToDXF()` | вывод на вершину с ненулевым bulge |
| Перенос bulge из DWG | `uzedwgentlwpolyline.pas` | из `Props.Vertices[i].Bulge` |
| Геометрия bulge→дуга | новый модуль `uze*bulge*.pas` | по образцу `ezdxf.math._bulge` |
| Тесселяция/quad дуги | `CalcWidthSegment()` | ветвление прямая/дуга |
| Linetype вдоль дуги | слой отрисовки (drawer) | раскладка по длине дуги |

## 10. Выводы и рекомендации для этапа проектирования

### 10.1. Главные выводы

1. **Bulge — лишь способ компактного хранения дуги** (одно число `tan(θ/4)` на вершину).
   Математика преобразования Bulge↔(центр, радиус, углы) проста, надёжна и хорошо документирована
   (раздел 3, эталон — `ezdxf.math._bulge`). Это **наименее рискованная** часть.
2. **Основная сложность — не Bulge, а корректная отрисовка дуги совместно с Width и Linetype**, и
   особенно стыковка соседних сегментов. Именно здесь сосредоточен технический риск (раздел 9.3).
3. **Width:** постоянная ширина на дуге строится точно (концентрические дуги). Переменная ширина и
   все стыки требуют тесселяции и аккуратной геометрии (miter по касательной, защита от выворота).
4. **Linetype:** обязателен учёт **длины дуги** (а не хорды), **непрерывности фазы** между
   сегментами и режима **PLINEGEN** (бит 128 кода 70).
5. **Инфраструктура ZCAD уже частично готова:** есть класс дуги `GDBObjArc`, quad-отрисовка ширины
   для прямых, а bulge уже доходит до уровня DWG-структуры — нужно лишь не отбрасывать его и
   обобщить геометрию.

### 10.2. Рекомендуемая поэтапность (для будущей реализации)

1. **Этап A — данные.** Добавить хранение bulge на вершину; читать/писать код 42 (DXF), переносить
   bulge из DWG/proxy. Результат: дуги сохраняются без потерь (round-trip), даже если рисуются ещё
   как хорды.
2. **Этап B — геометрия.** Отдельный модуль формул bulge→дуга (центр, радиус, углы, длина, точка,
   касательная, BBox) с юнит-тестами по числовому примеру из раздела 3.5.
3. **Этап C — отрисовка тонких дуг.** Тесселяция дуговых сегментов в осевую линию (адаптивно по
   LOD). Корректные BBox, привязки, длина, площадь.
4. **Этап D — Width.** Постоянная ширина (кольцевой сектор) → переменная ширина (тесселяция) →
   стыки (miter/bevel) → защита от выворота.
5. **Этап E — Linetype.** Раскладка по длине дуги, накопленная фаза, режим PLINEGEN.

Такой порядок даёт работающий результат уже после этапа A (нет потери данных) и B–C (видимые дуги),
а самые сложные части (Width-стыки, Linetype) выносятся в конец.

### 10.3. Тестовая база

Файл `cad_source/test/polylinearc.dxf` — минимальный воспроизводимый пример (прямая полилиния +
полилиния с одним дуговым сегментом). Для полноты будущего тестирования рекомендуется дополнить
набор файлами с: переменной шириной на дуге; замкнутой полилинией с дугой; малым радиусом и большой
шириной; типами линий DASHED/HIDDEN/CENTER на дугах; режимом PLINEGEN.

### 10.4. Что НЕ входит в текущий этап

В соответствии с ТЗ задачи #1295 на данном этапе **не выполняется**: написание кода, изменение
реализации ZCAD, проектирование классов, реализация Bulge/отрисовки/UI. Настоящий документ —
исключительно аналитическое исследование предметной области и оценка сложностей.

## 11. Источники и изученные материалы

### 11.1. Спецификации формата DXF

* DXF Reference (Autodesk), сущность **LWPOLYLINE** — групповые коды 90, 70, 43, 38, 10/20, 40, 41,
  **42 (Bulge)**, 91, 210/220/230.
* DXF Reference (Autodesk), сущности **POLYLINE** / **VERTEX** / **SEQEND** — классическое
  представление полилинии; код **42 (Bulge)** у `VERTEX`.
* DXF Reference, переменные заголовка: `$FILLMODE`, `$LTSCALE`, `$CELTSCALE`, `$PLINEGEN`.

### 11.2. Библиотека ezdxf (https://github.com/mozman/ezdxf)

* `src/ezdxf/entities/lwpolyline.py` — класс `LWPolyline`, формат вершины `(x, y, start_width,
  end_width, bulge)`.
* `src/ezdxf/entities/polyline.py` — `Polyline`/`DXFVertex`, атрибут `bulge`.
* `src/ezdxf/math/_bulge.py` — функции `bulge_to_arc`, `bulge_center`, `bulge_radius`,
  `arc_to_bulge`.
* `src/ezdxf/math/arc.py`, `src/ezdxf/math/_construct.py` — построение дуг, точки, BBox.
* `src/ezdxf/path/` — адаптивная аппроксимация геометрии (включая дуги из bulge) отрезками.
* `ezdxf.addons.drawing` (в т. ч. `line_renderer`) — отрисовка ширины и раскладка Linetype на
  уровне рендер-слоя.
* Документация ezdxf: разделы «Bulge», «LWPolyline», «Path».

### 11.3. Документация AutoCAD

  (дуга → `ARC`).
