
# 🔴 Критические слабые места (must-fix)

## 1. ❗ Нет чёткой модели данных инспектора

Судя по ТЗ, инспектор — это “консоль + просмотр DWG”, но:

👉 не определено:

* что является **единицей инспекции** (entity? object? handle? raw struct?)
* есть ли **единый объект-узел (node)** дерева
* как представляются связи (ownership / reference / reactors)

📌 Почему это критично
DWG — это **граф объектов**, а не список. Без модели:

* нельзя нормально строить дерево
* нельзя делать lazy-loading
* нельзя дебажить связи

👉 Что добавить:

* базовый интерфейс:

  ```text
  IInspectorNode
    - handle
    - type
    - parent
    - children[]
    - rawDataRef
  ```
* разделить:

  * logical node (иерархия)
  * raw node (данные из libredwg)

---

## 2. ❗ Нет двухфазной загрузки (очень серьёзно)

Ты уже сам поднимал это — и тут реально дырка.

Сейчас (по ТЗ) всё выглядит как:

> загрузили → сразу используем

Но DWG требует:

### Фаза 1 — чтение

* прочитали все объекты
* сохранили handle → объект
* без связей

### Фаза 2 — резолв ссылок

* owner
* reactors
* soft/hard pointers

📌 Без этого:

* будут dangling ссылки
* циклы развалят логику
* инспектор будет показывать мусор

👉 Нужно явно прописать:

* pipeline загрузки
* состояние объекта:

  * RAW
  * RESOLVED
  * FAILED

---

## 3. ❗ Игнорируется сильная сторона libredwg

libredwg — это:

* доступ к **низкоуровневым структурам**
* почти 1:1 с DWG

Но ТЗ, судя по описанию, не использует это:

👉 нет:

* отображения raw структуры
* dump-представления
* byte-level инспекции

📌 В итоге получится “урезанный AutoCAD viewer”, а не инспектор

👉 Что добавить:

* режимы:

  * logical view
  * raw struct view
  * hex / dump (опционально)
* возможность видеть:

  * поля struct
  * offsets
  * типы

---

## 4. ❗ Нет политики unsupported объектов

DWG всегда содержит:

* неизвестные классы
* proxy objects
* версии новее библиотеки

👉 Сейчас:
не описано, что делать

📌 Это гарантированно приведёт к:

* падениям
* silent loss данных
* непредсказуемому UI

👉 Нужно:

* тип UNKNOWN_OBJECT
* fallback:

  * raw dump
  * hex
* логирование:

  * warning, не error

---

## 5. ❗ Нет стратегии ошибок (очень опасно)

Не описано:

* что делать при:

  * битом DWG
  * частично прочитанном объекте
  * ошибке парсинга

📌 В инспекторе это критично: он должен **жить даже на мусоре**

👉 Добавь:

* уровни:

  * fatal (файл не открыть)
  * recoverable (объект пропущен)
  * warning
* режим degraded:

  * показываем всё, что смогли

# 📘 Техническое задание

## DWG Console Inspector (production-ready версия)

---

# 1. 🎯 Цель системы

Разработать консольный инструмент для **инспекции структуры DWG-файлов**, обеспечивающий:

* безопасную загрузку DWG (включая повреждённые)
* отображение графа объектов DWG
* навигацию по связям (ownership, references)
* просмотр как логической структуры, так и raw-данных
* отладку парсинга и структуры файла

---

# 2. 🧱 Архитектура системы

Система должна быть строго разделена на слои:

```text
[ DWG Loader ]  ->  [ Resolver ]  ->  [ Inspector Model ]  ->  [ Console UI ]
       ↓                 ↓                    ↓                    ↓
   Raw objects      Object graph         Node tree           Commands
```

---

## 2.1. Layer 1 — DWG Loader

### Ответственность:

* загрузка DWG через libredwg
* формирование **сырых объектов (raw objects)**
* отсутствие логики связей

### Выход:

```text
TRawDWG:
  - objects: TRawObject[]
  - handleMap: Map<Handle, TRawObject>
  - metadata (version, header, etc.)
```

### TRawObject:

```text
handle: UInt64
type: string
rawPtr: pointer (libredwg struct)
size: int (optional)
status: RAW | ERROR
```

---

## 2.2. Layer 2 — Resolver

### Ответственность:

* построение **графа объектов**
* разрешение ссылок:

  * owner
  * hard/soft pointers
  * reactors

### Выход:

```text
TResolvedGraph:
  - nodes: Map<Handle, TResolvedObject>
```

### TResolvedObject:

```text
handle: UInt64
type: string

owner: Handle?
children: Handle[]

hardRefs: Handle[]
softRefs: Handle[]

reactors: Handle[]

raw: TRawObject
status: RESOLVED | PARTIAL | FAILED
```

---

### ⚠️ Обязательное требование:

Resolver работает **в 2 фазы**:

#### Фаза 1:

* создать все TResolvedObject без связей

#### Фаза 2:

* установить ссылки между объектами

---

## 2.3. Layer 3 — Inspector Model

### Ответственность:

* предоставить удобную модель для UI
* абстрагировать граф в **инспектируемые узлы**

### Основной интерфейс:

```text
IInspectorNode:
  getHandle(): UInt64
  getType(): string

  getParent(): IInspectorNode?
  getChildren(): IInspectorNode[]

  getRefs(): IInspectorNode[]
  getRaw(): TRawObject

  getStatus(): OK | PARTIAL | BROKEN
```

---

### Дополнительно:

* lazy loading children (по требованию)
* кэширование узлов

---

## 2.4. Layer 4 — Console UI

### Ответственность:

* реализация CLI
* выполнение команд
* отображение данных

---

# 4. ⚠️ Обработка ошибок

Система НЕ должна падать на некорректных DWG.

---

## 4.1. Уровни ошибок

```text
FATAL     — файл не открыт
ERROR     — объект не прочитан
WARNING   — частичная потеря данных
INFO      — диагностическая информация
```

---

## 4.2. Поведение

| Ситуация           | Поведение            |
| ------------------ | -------------------- |
| неизвестный объект | создать UNKNOWN      |
| битая ссылка       | сохранить как BROKEN |
| ошибка парсинга    | пропустить объект    |
| частичные данные   | статус PARTIAL       |
