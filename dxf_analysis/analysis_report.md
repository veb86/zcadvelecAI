# Анализ структурных различий DXF файлов

## Исходные данные

- **Оригинальный файл** (AutoCAD открывает): `testspds3entity_original.txt` (23 668 строк)
- **Сохранённый ZCAD файл** (AutoCAD отклоняет): `testspds3entity333.txt` (23 074 строки)
- **Ошибка AutoCAD**: "Словарь GroupTable не был определен в словаре NamedObject"
- **Вторичная ошибка**: "Expected group 280 (zombie flag) at line 922"

---

## Краткое резюме

Проблема **не** в пустом словаре ACAD_GROUP. Оба файла содержат одинаково пустой словарь ACAD_GROUP. Реальная причина ошибки — **понижение версии DXF-формата** с AC1021 до AC1015 при сохранении ZCAD.

---

## Найденные различия (по убыванию критичности)

### 1. КРИТИЧНО: Версия DXF формата — AC1021 → AC1015

| Параметр | Оригинал | Сохранённый ZCAD |
|----------|----------|------------------|
| `$ACADVER` | `AC1021` (AutoCAD 2007) | `AC1015` (AutoCAD 2000) |
| `$ACADMAINTVER` | `50` | `10` |
| `$LASTSAVEDBY` | `BobrovV` | *(отсутствует)* |

**Местоположение в оригинале**: строки 5–8
**Местоположение в сохранённом**: строки 5–8

ZCAD сохраняет файл в формате AC1015, несмотря на то что исходный файл был AC1021. При этом в файл включаются объекты, специфичные для AC1021 (`ACDBDETAILVIEWSTYLE`, `ACDBSECTIONVIEWSTYLE`). Это вызывает конфликт при разборе AutoCAD.

---

### 2. КРИТИЧНО: В секции CLASSES отсутствует группа 91 (счётчик экземпляров)

В формате AC1021 каждая запись CLASS содержит группу `91` (instance count) между группами `90` и `280`. В формате AC1015 группа `91` отсутствует.

**Оригинал** (строки 1127–1134 — класс `ACDBDICTIONARYWDFLT`):
```
 90
        0
 91        ← ПРИСУТСТВУЕТ в оригинале
        1
280
     0
281
     0
```

**Сохранённый ZCAD** (строки 919–924 — тот же класс):
```
 90
        0
280        ← ОТСУТСТВУЕТ группа 91, сразу идёт 280
     0
281
     0
```

**Это объясняет вторичную ошибку**: "Expected group 280 (zombie flag) at line 922"

AutoCAD версии 2007+ при разборе файла с объектами AC1021 ожидает группу `91` после группы `90`. Когда он находит `280` на строке 921 (где ожидал `91`), сбивается парсер. Затем на строке 922 (значение группы 280, т.е. `     0`) он ожидает найти саму группу `280` — отсюда сообщение об ошибке.

**Статистика**: в оригинале 9 классов из 18 содержат группу `91`; в сохранённом — ни один из 18.

Классы, где `91` присутствует в оригинале но отсутствует в сохранённом:
- `TABLESTYLE`
- `MATERIAL`
- `VISUALSTYLE`
- `SCALE`
- `MLEADERSTYLE`
- `CELLSTYLEMAP`
- `EXACXREFPANELOBJECT`
- `NPOCOLLECTION`
- `ACDBSECTIONVIEWSTYLE`
- `ACDBDETAILVIEWSTYLE`
- `SPDSPOLYMORPHMARK`
- `SPDSNOTEPOSITION`

### 3. КРИТИЧНО: Отсутствие группы 330 (ссылка на владельца) в сущностях ENTITIES

В сохранённом файле все три сущности `ACAD_PROXY_ENTITY` в секции ENTITIES **не имеют** группы `330` (ссылку на блок-владелец).

**Оригинал** (строки 2789–2798 — `SPDSPOLYMORPHMARK`, дескриптор `2F7`):
```
  0
SPDSPOLYMORPHMARK
  5
2F7
330          ← ПРИСУТСТВУЕТ: ссылка на Model_Space (1F)
1F
100
AcDbEntity
```

**Сохранённый ZCAD** (строки 2303–2311 — `ACAD_PROXY_ENTITY`, дескриптор `3B`):
```
0
ACAD_PROXY_ENTITY
5
3B
100          ← ОТСУТСТВУЕТ группа 330!
AcDbEntity
```

Все три `ACAD_PROXY_ENTITY` (дескрипторы `3B`, `3C`, `3D`) лишены группы `330`.
Ожидаемое значение: `330` = `2F` (дескриптор *Model_Space в сохранённом файле).

---

### 4. ЗНАЧИМО: Тип сущности изменён с кастомного на прокси

| Тип сущности | Оригинал | Сохранённый |
|---|---|---|
| `SPDSPOLYMORPHMARK` | 2 штуки | 0 (заменены на прокси) |
| `SPDSNOTEPOSITION` | 1 штука | 0 (заменена на прокси) |
| `ACAD_PROXY_ENTITY` | 0 | 3 |

ZCAD не поддерживает запись кастомных сущностей `SPDSPOLYMORPHMARK` и `SPDSNOTEPOSITION`, поэтому сохраняет их как `ACAD_PROXY_ENTITY`. Это само по себе допустимо, однако вместе с проблемой отсутствия группы `330` делает файл некорректным.

---

### 5. УМЕРЕННО: Переназначение всех дескрипторов (перенумерация)

ZCAD полностью переназначает дескрипторы объектов при сохранении, используя последовательную нумерацию начиная с `3E` (hex).

| Ключ NOD | Дескриптор оригинала | Дескриптор сохранённого |
|---|---|---|
| NOD (корень) | `C` | `3E` |
| ACAD_GROUP | `D` | `42` |
| ACAD_LAYOUT | `1A` | `43` |
| ACAD_PLOTSTYLENAME | `E` | `48` |
| spds.net.allocationrange | `2BC` | `51` |
| ... (все остальные) | произвольные | последовательные |

Перенумерация сама по себе допустима, однако все ссылки должны быть корректно обновлены. Анализ показывает, что ссылки из NOD корректно указывают на новые дескрипторы.

**Примечание**: дескрипторы в XDATA (расширенные данные) в `ACAD_PROXY_ENTITY` содержат `_OWNERHANDLE=0000000064` (64 десятичных = 0x40 hex). В сохранённом файле дескриптор `0x40` — это `ACAD_COLOR` dictionary. Это указывает на то, что XDATA из исходных сущностей содержит оригинальные дескрипторы, не перемаппированные.

### 8. МИНОРНО: Различие форматирования (отступы)

- Оригинал: коды групп имеют ведущие пробелы (`  0`, `  5`, ` 90`)
- Сохранённый (большинство секций): без отступов (`0`, `5`, `90`)
- Секция OBJECTS в сохранённом: **смешанное** форматирование (часть строк с отступами — те, что скопированы из оригинала; часть без — написанные ZCAD)

Это не влияет на корректность разбора, так как DXF-парсеры игнорируют ведущие пробелы.

Словарь NOD (Named Objects Dictionary) в обоих файлах содержит одинаковый набор 52 ключей, включая `ACAD_GROUP`. Структура корректна в обоих файлах.

**Вывод**: ACAD_GROUP dictionary **идентичен** в обоих файлах (пустой, корректно владеющий NOD).

## Диагностика ошибки AutoCAD

### Ошибка "Expected group 280 (zombie flag) at line 922"

**Причина**: В сохранённом файле секция CLASSES не содержит группу `91` (instance count) в записях CLASS. AutoCAD 2007+ при наличии объектов формата AC1021 ожидает группу `91` после `90`. Парсер находит `280` вместо ожидаемого `91`, сбивается с ритма разбора, и затем на строке 922 (значение `     0`) ожидает найти сам код группы `280`.

### Ошибка "GroupTable dictionary not defined in NamedObject dictionary"

**Причина**: Это **вторичная** ошибка, возникающая после сбоя парсера из-за несоответствия форматов. Когда AutoCAD не может корректно разобрать секцию CLASSES (из-за отсутствия группы `91`), его внутреннее состояние нарушается. При попытке восстановления или дальнейшего разбора он не может найти словарь GroupTable в NOD, хотя физически он там присутствует.

**Дополнительный фактор**: Сущности `ACAD_PROXY_ENTITY` без группы `330` (владелец) нарушают целостность графа владения объектами.

## Рекомендации по исправлению

### Приоритет 1 — Исправить версию DXF

ZCAD должен сохранять `$ACADVER = AC1021` если исходный файл был AC1021. Либо, если ZCAD принудительно сохраняет в AC1015, он должен:
1. Убедиться, что все объекты совместимы с AC1015 (убрать `ACDBDETAILVIEWSTYLE`, `ACDBSECTIONVIEWSTYLE` если они требуют AC1021)
2. Сохранять CLASS-записи в формате AC1015 (без группы `91`) — **это уже делается корректно**

### Приоритет 2 — Добавить группу 330 к ACAD_PROXY_ENTITY

При записи `ACAD_PROXY_ENTITY` в секцию ENTITIES необходимо добавлять группу `330` с дескриптором блока-владельца (для модельного пространства — дескриптор записи `*Model_Space` в таблице `BLOCK_RECORD`).

В сохранённом файле дескриптор `*Model_Space` = `2F`. Поэтому сущности должны содержать:
```
0
ACAD_PROXY_ENTITY
5
<дескриптор>
330     ← добавить
2F      ← дескриптор *Model_Space
100
AcDbEntity
...
```

### Приоритет 3 — Сохранять CLASS-записи в правильном формате

Если файл сохраняется как AC1021, CLASS-записи должны содержать группу `91`. Если как AC1015 — без группы `91`. Сейчас ZCAD записывает классы без `91`, что соответствует AC1015, но заголовок `$ACADVER` должен совпадать.

---

## Схема потока обработки ошибки

```
AutoCAD открывает файл AC1021
↓
Читает $ACADVER = AC1015
↓
Находит объекты AC1021 (ACDBDETAILVIEWSTYLE и др.)
↓
Пытается разобрать CLASSES в режиме AC1021
↓
Ожидает группу 91 после 90, но находит 280
↓
Парсер CLASS сбивается → "Expected group 280 at line 922"
↓
Внутреннее состояние NOD не построено корректно
↓
"GroupTable dictionary not defined in NamedObject dictionary"
```
